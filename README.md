Команда **znatalk.ai** · задача «Сервис формирования цифрового признака транспортного средства
для сопоставления снимков одного автомобиля из разных локаций без использования

## Что делает решение

Сервис находит тот же автомобиль на снимках с разных камер только по внешнему виду.
Оператор загружает кадр, выделяет рамку (bbox) и получает ранжированный список кандидатов
или откалиброванный отказ от идентификации. Текст номера, OCR, камера и время **не являются
входами энкодера**.

Выбранная модель DINOv3 ViT-L/16 (вариант TT) даёт **92.0048 % mAP@10 на development-данных
SEARCH** и **87.0033 % на ранее уже открытом audit-фолде**. Повторное обучение FIT с нуля
(fresh FIT retrain) дало **91.2127 %**. Финальное офлайн-извлечение нативным кодом в Linux:
**22.42–24.58 мс медиана при batch=1 / 181.55–185.94 FPS** на RTX 3090. Это локальные
измерения, а не результаты скрытого теста жюри. Подробности — в
[полной проверке и ограничениях](docs/submission-readiness.md).

## Быстрый старт

Организаторы подтвердили, что для проверки достаточно воспроизводимого Docker-стенда с кодом,
весами и инструкцией запуска. В репозитории два независимых пути запуска.

**Требования:** Docker с Docker Compose v2, [Git LFS](https://git-lfs.com) (веса модели,
607 325 498 байт, лежат в LFS), для образа жюри — Linux x86_64, GPU NVIDIA с CUDA,
[NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/)
и [`just`](https://github.com/casey/just). Кадры датасета (`dataset/images/`, около 7.5 ГБ)
в git не входят; их нужно положить в `dataset/images/`.

### 1. Сервис оператора одной командой

```sh
git lfs install && git lfs pull        # веса models/model.onnx
cp .env.example .env && docker compose up --build
```

После сборки интерфейс открывается на http://localhost:3000 (адреса — в разделе
«Прототип оператора» ниже). Сервисный инференс по умолчанию идёт через ONNX Runtime на CPU.

### 2. Офлайн-образ жюри (три файла сдачи одной командой)

```sh
git lfs install
git lfs pull
just submit-image
docker run --rm --network none --gpus all   -v /absolute/path/to/data:/data:ro -v "$PWD/submission:/out" reid-submit   --images /data/images --query /data/test_query.csv --gallery /data/test_gallery.csv --out /out
just perf-gpu
python ml/scripts/verify_submission.py --submission submission   --query dataset/test_query.csv --gallery dataset/test_gallery.csv --manifest models/model.json
```

`just submit-image` — это `docker build --platform linux/amd64 -f deploy/submit.Dockerfile
-t reid-submit .` (интернет нужен только при сборке). `just perf-gpu` — замер скорости по
протоколу жюри и двукратная проверка побайтовой повторяемости; каталог результата
(`perf-gpu/` по умолчанию) не должен существовать заранее. Для `verify_submission.py` на хосте
нужен Python 3 с `numpy`; та же проверка встроена в образ (`/opt/lct/verify_submission.py`).

Образ содержит нативный Rust/ONNX CUDA и ускоренный Python-вход `extract(path,bbox)`.
Он требует CUDA, отключает PTX JIT и **не переходит молча на CPU**. У инференса нет сетевых
зависимостей. Модель размером 607 325 498 байт лежит в Git LFS; промежуточные веса обучения
в каталог сдачи не входят.

Три файла сдачи: `submission.csv` (топ-10 без заголовка для каждого запроса),
`candidates.csv` (только принятый топ-1) и `embeddings.npy` (float32, сначала query, затем
gallery, 1 024 измерения). Оба полных прогона дали побайтно одинаковый результат и прошли
независимую проверку. [submission/run.json](submission/run.json) фиксирует точные хеши.

Офлайн-ранжирование использует статический DBA только по галерее k=4 / alpha=2, порог
**0.720700740814209**. Живой сервис на pgvector использует обычный косинус и порог
**0.6959864497184753**. Пороги не взаимозаменяемы. Запросы обрабатываются независимо.
При смене версии модели живая галерея переиндексируется под версию **1.2.0-final**;
векторы разных версий не смешиваются.

## Прототип оператора

Прототип развёрнут на **https://lct.znatalk.ai**: живой сервис использует модель
**1.2.0-final** и порог обычного косинуса **0.6959864497184753**. Локальный запуск:

```sh
cp .env.example .env
docker compose up --build
# Необязательные GPU-сервисы:
docker compose -f docker-compose.yml -f docker-compose.gpu.yml up --build
```

| Адрес | Назначение |
|---|---|
| http://localhost:3000 | Поиск по кадру и bbox, сравнение кандидатов, экспорт CSV |
| http://localhost:3000/gallery | Управление галереей и импорт |
| http://localhost:3000/solution | Модель, доказательства, режим отказа и ограничения |
| http://localhost:3000/api/docs | OpenAPI / Swagger UI |
| http://localhost:3000/api/health | Готовность сервисов |
| http://localhost:3000/api/info | Загруженная модель, версия, провайдер |
| http://localhost:3000/route/959 | Симуляция маршрута; для карты нужен YMAPS_KEY |

Импорт галереи из смонтированного датасета:

```sh
curl -F csv=@dataset/test_gallery.csv -F images_dir=images http://localhost:3000/api/gallery/import
```

Интерфейс сделан на React/Vite; API-шлюз на Rust маршрутизирует gRPC-запросы в сервисы
inference, gallery, search и необязательный tagger. PostgreSQL/pgvector хранит реляционные
данные и векторы. Docker Compose поднимает весь стек. Маршрут на карте и визуальный теггер —
демонстрационные функции вне офлайн-конвейера жюри. Распознавание номеров в инференс модели
не входит.

## Обучение и доказательства

DINOv3 foundation → публичный VERI-Wild TRAIN E2 → TRAIN+публичный TEST E1 → конкурсный
FIT-v8 (5 722 строки, 928 ID, восемь эпох, сэмплер 2+2). Проверены все 416 314 внешних
изображений и 11 416 конкурсных; точных пересечений по файлам, RGB и кропам — ноль.
Ответ организаторов Q46 разрешает публичные внешние тестовые сплиты. Входы жюри в обучение
никогда не попадали. Исторические 24 исключения из FIT раскрыты; новой чистки и
переразметки не было.

## Ограничения

- SEARCH многократно использовался при разработке. Calibration/audit уже открывались для
  предыдущей модели, поэтому заявления о нетронутом тесте **нет**.
- Audit Q режима отказа равен 0.9365 (ниже, чем 0.9581 у предыдущей модели), при этом audit
  mAP вырос на 2.4806 пункта.
- Приблизительное маскирование зоны номера снизило SEARCH mAP на 0.7124 пункта; это не
  точный тест жюри с масками.
- Драйвер 535 / RTX A5000 локально не проверены.
- Метрики и место на скрытом тесте жюри неизвестны.

## Разработка и тесты

```sh
# Перед тестами паритета модели установить Python-рантайм инференса:
cd ml && uv sync --group dev && uv pip install -r requirements-submit.txt && cd ..
just test
just lint
cd web && npm test && npm run build
```

Rust-сервисы в модульных тестах используют моки зависимостей; база данных не нужна.
Python-набор проверяет входы обучения, расширение оптимизатора, калибровку, поведение при
отказе CUDA и независимую проверку предсказаний. Нативные тесты покрывают паритет
препроцессинга и ранжирования. CI также собирает веб-интерфейс.
